# FlashH3VR

**Flash H3 Video Restoration · 基于 H3 的高效人像视频修复**

[English](README.md) · [使用与环境](docs/USAGE.md) · [基线记录](docs/BASELINE.md) · [许可说明](THIRD_PARTY_NOTICES.md)

FlashH3VR 使用冻结的 MiniMax H3 视频 VAE、动态头部裁剪与 NAFNet 末端适配，为人像视频生成空间修复量，再回贴到原始画面，保留真实时间戳。

**当前发布的是研究源码。适配检查点、第三方模型权重、训练数据与演示视频均未包含；仅克隆仓库无法复现已报告的修复效果。** 权重和数据的使用条件独立于代码协议，详见[资源与发布边界](docs/ASSETS.md)。

## 当前版本

- 接受的权重：平衡 32 步 NAF 末端适配，199,747 个适配参数；后续空间实验未替换它。
- 执行配置：YOLO11m-face / FP32 / 960 / 双路 batch16，读帧与检测重叠，direct BGR。
- H3：原生 22 帧、重叠 5 帧，固定 INT8 ConvRot 权重与 Comfy Kitchen CUDA INT8 实现。
- 头部桶为 256 像素；NAF batch8。当前文件路径处理无音轨 SDR 视频。

## 已有实测

以下均在 **RTX PRO 6000 Blackwell 96 GB** 上，对 **60 帧、60 fps、768 × 432** 输入完整执行一遍。推理耗时不含加载；吞吐量不等于输入帧率或流式实时能力。

| 测量 | 推理耗时 | 吞吐 | 单独加载 |
|---|---:|---:|---:|
| 9 月 11 日接受基线 | 2.440212 秒 | 24.588 FPS | 4.953044 秒 |
| 9 月 12 日附资源采样收口验证 | 2.539637 秒 | 23.625 FPS | 6.314069 秒 |

收口输出与接受基线的浮点结果、检测几何、编码帧和 MP4 逐位一致。新一遍比历史慢约 4.07%，未归因于单一因素，也未替换历史基线；尚无重复统计。

收口时 CPU 全机平均 **13.01%**，测试进程平均使用约 **2.31 个核心**；GPU 设备平均 **52.21%**、峰值 **99%**。框架分配/保留显存峰值 **6.190 / 9.785 GiB**；包含后台程序的设备显存峰值 **13.223 GiB**。

历史 Johnny 评估相对退化输入的 LPIPS 改善 **5.848%**，高频误差改善 **1.211%**。这些是限定样本和条件下的结果，不能推广为通用画质领先。完整口径见[基线文档](docs/BASELINE.md)。

## 安装与 CPU 验证

记录中的开发环境是 Python 3.12。先在独立环境安装适合平台的 PyTorch 和 torchvision，再执行：

```bash
python -m pip install -e ".[dev,video,models]"
python -m pytest -q
```

测试使用合成输入与 CPU 检查，不下载模型权重，不代表完整模型验收。Python 模块名暂保留 `h3ce`；安装包和项目展示名为 **FlashH3VR**。

旧 `h3ce` 命令尚未接入当前接受的完整 NAF 文件推理配置。研究 API、外部依赖和缺失资产见[使用说明](docs/USAGE.md)。历史实验脚本依赖未公开的缓存和记录，不能直接当作新环境的一键训练命令。

## 后续方向

当前研究阶段已经收口，停止时序优化和探索性训练；保留已有 H3 时序、动态几何和时间戳处理。后续优先解决适配权重的发布条件、可移植推理入口、音轨处理与更多硬件验证。NAF 角色 LoRA、512 头部尺寸和 24/48 GB 显卡验证仍未完成。
